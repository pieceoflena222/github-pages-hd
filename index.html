01
Practice 01 · 메타프롬프팅

AI가 계획하고 질문하게 하기

결과를 바로 요청하지 않고, AI가 먼저 분석 순서와 구성을 계획한 뒤 완성도를 높이는 데 필요한 정보를 스스로 질문하도록 유도하는 프롬프트입니다.

공통 상황 실습 1·2에서 함께 사용합니다 
엔진 생산라인의 주간 가동 결과를 집계한 결과, 총 정지시간은 2,048분이었다. 주요 원인은 설비고장 1,255분, 자재부족 430분, 품질문제 250분이며, 전주보다 총 정지시간이 18% 증가했다. 세부 조치계획과 담당자는 미정이다.

먼저 이 상황을 AI에게 전달한 뒤, 아래 프롬프트를 이어서 입력하세요.

Prompt 계획 + 질문 유도 
위 내용을 바탕으로 생산 차질 결과보고서를 작성하려고 해.
 바로 작성하지 말고, 먼저 분석 순서와 보고서 구성을 계획한 다음, 완성도 높은 보고서를 위해 추가로 필요한 정보를 질문해줘.

TIP — 계획 수립과 정보 확인을 한 번에 요청하는 방식입니다. 프롬프트의 "위 내용"은 앞에서 복사한 공통 상황을 가리킵니다.

02
Practice 02 · 메타프롬프팅

프롬프트를 개선하고 실행하게 하기

AI의 질문에 답한 내용을 반영해, AI 스스로 더 구체적인 프롬프트로 다듬은 뒤 바로 실행하도록 요청하는 프롬프트입니다.

Prompt 프롬프트 개선 + 실행 
지금까지의 내용과 내 답변을 반영해서, 보고서 작성에 적합한 구체적인 프롬프트로 개선해줘.

TIP — 프롬프트가 만들어지면 이어서 "그 프롬프트에 따라 결과보고서 초안을 작성해줘"라고 요청해보세요.

03
Practice 03

업무 언어로 시작하는 바이브코딩

코드를 바로 요청하지 않고, AI가 기획자처럼 질문하며 웹페이지 설계안을 먼저 정리하도록 지시하는 시작 프롬프트입니다.

Prompt 기획 질문 유도 
나는 [생산 차질 원인을 분석하는 업무]를 더 편하게 할 수 있는 웹페이지를 만들고 싶습니다.
사용할 데이터는 [엑셀/CSV 파일]이고,
최종적으로 [주요 현황과 문제 원인을 한눈에 확인]하고 싶습니다.
아직 코드를 만들지 마세요.
내 업무에 실제로 필요한 웹페이지가 되도록 당신이 기획자처럼 필요한 사항을 먼저 질문해주세요.
질문은 한꺼번에 많이 하지 말고 가장 중요한 질문부터 하나씩 진행해주세요.
가능한 질문은 내가 직접 문장을 입력하지 않아도 되도록 객관식 선택지로 만들어주세요.
사용 중인 환경에서 지원된다면 선택지를 버튼처럼 직접 클릭해서 답할 수 있는 클릭형 방식으로 제시해주세요.
- 한 번에 질문 1개
- 선택지는 가능하면 3~5개
- 잘 모르겠어요 / 추천해주세요 선택지도 필요한 경우 포함
- 내 답변에 따라 다음 질문을 달리해주세요.
- 객관식으로 해결하기 어려운 내용만 짧게 추가 질문해주세요.
- 개발 용어보다 실제 업무 담당자가 이해하기 쉬운 표현을 사용해주세요.
충분한 정보가 모이면 코드를 바로 작성하지 말고 먼저
① 필요한 기능
② 화면 구성
③ 데이터 분석 방식
④ 꼭 필요한 예외처리
를 정리한 웹페이지 설계안을 보여주세요.
내가 설계안을 검토하고 "좋아, 만들어줘"라고 말하면 그때 최종 웹페이지 코드를 작성해주세요.

TIP — 대괄호 [ ] 안의 내용은 실제 담당 부서의 업무에 맞게 바꿔서 입력하세요.

04
Practice 04

설계안 확정 후 웹페이지 구현 요청

AI가 제시한 설계안을 검토한 뒤, 실제 동작하는 HTML 대시보드로 완성해달라고 요청하는 프롬프트입니다.

Prompt 대시보드 구현
실습 파일 다운로드 
좋아요. 이 설계대로 만들어주세요.
별도 프로그램 설치 없이 PC에서 실행할 수 있도록 하나의 HTML 파일로 완성해주세요.
파일을 업로드하면 브라우저 안에서 처리되도록 하고, 디자인은 실제 회사에서 사용할 수 있는 전문적인 업무용 대시보드로 만들어주세요.

완성된 대시보드가 만들어지면 실습파일1을 업로드해 실제로 동작하는지 확인해보세요.

05
Practice 05

사용해보고, 내 업무에 맞게 고도화하기

완성된 웹페이지를 써본 뒤, 실제 피드백을 주듯 세 가지 방향으로 다듬어달라고 요청하는 예시 프롬프트입니다.

5.1필요한 기능만 남기고 추가하기 
전체적으로 잘 만들어졌어.
시간대 분석은 우리 업무에서는 필요 없으니 빼줘.
대신 설비별 정지시간 TOP 5를 추가해줘.
가장 중요한 생산차질 원인이 첫 화면에서 더 잘 보이게 해줘.
기존에 잘 작동하는 기능은 그대로 유지해줘.
5.2첫 화면을 더 보기 쉽게 
차트가 많아서 처음 봤을 때 조금 복잡해.
핵심 KPI 4개와 중요한 차트 3개만 첫 화면에 보여주고, 나머지는 상세보기로 접어줘.
문제가 큰 항목은 한눈에 구분되게 강조해줘.
5.3실제 사용할 때 불편한 부분 개선하기 
파일을 잘못 올렸을 때 바로 다시 업로드할 수 있는 버튼을 추가해줘.
데이터 형식이 맞지 않을 때는 단순히 오류라고 하지 말고, 어떤 항목을 확인해야 하는지 쉽게 안내해줘.
처음 사용하는 직원도 어렵지 않게 사용할 수 있게 다듬어줘.
06
Practice 06

데이터를 읽고 설명하는 '인사이트 기능' 추가하기

외부 API 없이, 업로드된 데이터와 계산 결과만으로 질문에 답하는 '데이터 질의 도우미'를 대시보드에 추가하는 프롬프트입니다.

Prompt 데이터 질의 도우미 
현재 완성된 대시보드에 '데이터 질의 도우미' 기능을 추가해주세요.
생성형 AI나 외부 API는 사용하지 않고, 현재 업로드된 데이터와 계산 결과만 이용해주세요.
대시보드 하단에
- 가장 큰 차질 원인은?
- 가장 영향이 큰 라인은?
- 미분류 비율은?
- 최근 증가한 항목은?
- 보고서 핵심 포인트는?
버튼을 만들어주세요.
버튼을 클릭하면 실제 계산값과 비율을 근거로 짧은 분석 문장을 보여주세요. 데이터로 확인할 수 없는 원인이나 대책은 추측하지 마세요.
각 분석 결과에는 '보고서에 포함' 기능을 넣고, 선택한 문장은 기존 보고서의 '종합 분석 및 주요 확인사항'에 자동으로 반영해주세요.
비교할 데이터가 부족한 경우에는 임의로 판단하지 말고 비교 가능한 데이터가 충분하지 않습니다라고 안내해주세요.
기존 대시보드·보고서·A4 인쇄 기능은 그대로 유지한 상태에서 최종 전체 코드를 수정해주세요.
Prompt 참고 · 기존 화면 유지 가드레일 
현재 대시보드의 화면 구성, 색상, 글꼴, 버튼 위치, 차트 형태, 카드 디자인, 여백을 그대로 유지해주세요. 기존 기능과 코드는 변경하지 말고, 요청한 기능을 구현하는 데 필요한 부분만 최소한으로 추가해주세요. 전체 디자인을 다시 구성하거나 기존 요소를 삭제·이동하지 마세요.

이미 화면이 변경되었다면?
기존 대시보드의 인터페이스를 이전 상태로 복원하고, 새로 요청한 기능만 추가해주세요. 화면 구성과 디자인 요소는 이전 버전을 기준으로 유지해주세요.

TIP — 기능 추가를 요청할 때 이 문장을 함께 붙이면, AI가 화면을 임의로 새로 디자인하는 것을 막을 수 있습니다.

07
Practice 07

대시보드를 보고서까지 확장하기

대시보드에서 선택한 핵심 데이터를 실제 제출·출력이 가능한 업무보고서 형식으로 재구성하는 프롬프트입니다.

Prompt 업무보고서 고도화 (전문) 
현재 완성된 웹페이지와 보고서 생성 기능을 유지하면서, **보고서 부분을 실제 기업·기관에서 제출하거나 출력해 사용할 수 있는 수준의 고품질 업무보고서 형태로 전면 고도화해 주세요.**

중요한 목적은 단순히 대시보드를 A4 화면에 옮기는 것이 아닙니다.

**대시보드에서 사용자가 선택한 핵심 데이터와 차트를 실제 보고서 문법에 맞게 재구성하여, 읽는 사람이 현황 → 핵심 결과 → 원인 → 관리 필요사항을 빠르게 이해할 수 있는 문서로 만드는 것**이 최종 목표입니다.

## 1. 기존 기능은 반드시 유지

현재 정상 작동하고 있는 다음 기능은 유지해주세요.

* 엑셀 파일 업로드
* 데이터 분석
* KPI 계산
* 필터
* 차트
* 표
* 대시보드 선택 기능
* `보고서에 포함` 기능
* 보고서 생성
* A4 보기
* 인쇄 / PDF 저장

기존 전체 코드를 불필요하게 새로 작성하지 말고, **현재 코드 구조를 먼저 분석한 뒤 보고서 생성 부분을 중심으로 개선**해주세요.

---

# 2. 보고서의 개념부터 변경

현재 보고서가 단순히 선택된 카드와 차트를 나열하는 방식이라면 이를 변경해주세요.

보고서는 반드시 다음 흐름으로 읽히도록 구성합니다.

**보고 개요 → 핵심 결과 → 세부 분석 → 주요 원인 → 관리 필요사항 → 상세 데이터**

대시보드의 시각적 요소를 그대로 복사하지 말고, **보고서에 적합한 순서와 크기로 다시 배치**해주세요.

---

# 3. 보고서 기본 구조

현재 데이터와 선택된 항목을 분석하여 필요한 섹션만 자동으로 구성해주세요.

기본 구조는 다음을 권장합니다.

### ① 보고서 헤더

상단에는 다음 정보를 정돈된 형태로 배치합니다.

* 보고서 제목
* 분석 대상
* 분석 기간
* 작성일
* 데이터 기준일

현재 데이터에서 확인할 수 없는 항목은 임의로 만들지 마세요.

보고서 제목은 현재 웹앱의 분석 목적을 기준으로 자연스럽게 사용하되, 사용자가 수정할 수 있도록 구성해도 좋습니다.

---

### ② 핵심 결과 요약

보고서 첫 부분에서 가장 중요한 수치가 즉시 보이도록 구성해주세요.

예:

* 총 발생 건수
* 총 누적 시간
* 최다 발생 원인
* 최대 영향 라인
* 주요 비율

선택된 KPI 중 가장 중요한 지표 3~5개를 중심으로 배치해주세요.

대시보드 카드처럼 지나치게 화려하게 만들지 말고, **보고서용 핵심 지표 박스**처럼 정돈해주세요.

---

### ③ 종합 분석

현재의 `회의용 요약 자동 생성`, `회의용 요약`과 같은 문구는 모두 제거해주세요.

대신 다음과 같이 보고서 목적에 맞는 명칭을 사용해주세요.

**종합 분석 및 주요 확인사항**

이 영역에서는 실제 데이터에서 확인되는 사실만 사용하여 핵심 결과를 간결하게 정리해주세요.

예:

* 전체 정지시간 중 가장 높은 비중을 차지하는 원인
* 발생 건수가 가장 많은 원인
* 가장 큰 영향을 받은 라인
* 특정 원인 또는 라인으로 집중되는 현상
* 이전 기간과 비교 데이터가 실제 존재하는 경우 증감 현황

중요:

**데이터에서 확인되지 않는 원인, 개선 효과, 예상 결과, 미래 전망은 절대 임의로 생성하지 마세요.**

분석 가능한 근거가 부족하면 해당 내용은 작성하지 않습니다.

# 4. 데이터 기반 문장 생성 원칙

보고서 문장은 반드시 현재 계산된 데이터에서 직접 확인할 수 있는 사실을 기반으로 작성해주세요.

예를 들어 데이터가 다음과 같다면

`설비고장 1,255분 / 전체 2,048분`

다음과 같이 작성할 수 있습니다.

`설비고장이 전체 정지시간 중 가장 큰 비중을 차지하며, 총 1,255분으로 집계되었습니다.`

하지만 다음과 같은 문장은 작성하면 안 됩니다.

`설비 노후화가 주요 원인으로 판단됩니다.`

원본 데이터에 설비 노후화 정보가 없다면 근거 없는 추론이기 때문입니다.

---

# 5. 시각화는 보고서용으로 재배치

선택된 차트는 그대로 나열하지 말고 **보고서 흐름에 맞게 배치**해주세요.

예:

### 원인 분석

* 발생 건수 기준 순위
* 누적 시간 기준 순위

### 라인 영향 분석

* 라인별 누적 정지시간

### 시간대 분석

* 시간대별 발생 건수 및 시간

차트 제목 역시 대시보드용 짧은 제목보다 보고서 문맥에 맞게 다듬어주세요.

예:

`파레토 분석`

보다는

`원인별 발생 건수 및 누적 정지시간 분석`

처럼 의미가 바로 전달되도록 합니다.

---

# 6. 불필요한 섹션 자동 제거

데이터가 없는 항목은 제목만 남겨두지 마세요.

예를 들어 이전 기간 데이터가 없다면

`기간 비교`

라는 제목 자체를 보고서에서 표시하지 않습니다.

선택되지 않은 차트나 분석 항목도 빈 공간이나 빈 제목으로 남기지 마세요.

**실제 내용이 존재하는 섹션만 보고서에 포함**해주세요.

---

# 7. 관리 필요사항 영역

보고서 하단에는 필요하면 다음 영역을 추가해주세요.

### 관리 필요사항

단, 여기도 AI가 임의로 해결책을 만들어내는 방식이 아니라 **현재 데이터에서 확인 가능한 관리 대상**을 정리하는 수준으로 작성합니다.

예:

* 누적 정지시간이 가장 높은 원인
* 반복 발생 빈도가 높은 원인
* 영향을 가장 많이 받은 라인
* 추가 확인이 필요한 데이터

`개선안을 자동 제안`하거나 근거 없는 조치를 생성하지 마세요.

사용자가 직접 내용을 입력할 수 있도록 **조치사항 / 담당자 의견 / 특이사항 입력란**을 선택적으로 제공하는 것도 좋습니다.

# 8. 실제 기업 보고서 같은 디자인

보고서 디자인은 웹 대시보드가 아니라 **기업 내부 업무보고서**를 기준으로 다시 설계해주세요.

다음 디자인 원칙을 적용해주세요.

* A4 문서 중심 레이아웃
* 흰색 배경
* 절제된 포인트 컬러 1개
* 명확한 제목 계층
* 과도한 그라데이션 사용 금지
* 과도한 그림자 사용 금지
* 과도하게 둥근 카드 디자인 지양
* 보고서 본문은 가독성을 최우선
* 숫자는 정렬하여 비교하기 쉽게 표현
* 표의 헤더와 본문을 명확히 구분
* 차트 주변에 충분한 여백 확보
* 동일한 글꼴 크기와 간격 체계 유지

화면에서 예쁜 대시보드보다는 **출력했을 때 전문적으로 보이는 문서**를 목표로 합니다.

---

# 9. A4 인쇄 품질 고도화

A4 인쇄 화면은 실제 문서처럼 보여야 합니다.

CSS의 print 스타일을 사용하여 다음을 구현해주세요.

* A4 기준 `210mm × 297mm`
* 적절한 상하좌우 여백
* 차트와 표가 페이지 중간에서 잘리지 않도록 처리
* KPI 영역이 페이지 사이에서 분리되지 않도록 처리
* 섹션 제목과 내용이 다른 페이지로 분리되지 않도록 가능한 범위에서 처리
* 인쇄 시 웹페이지 버튼과 메뉴 숨김
* 배경색과 테두리가 필요한 부분은 인쇄에서도 유지
* 지나치게 작은 글씨 사용 금지
* 여러 페이지인 경우 자연스럽게 페이지가 구분되도록 처리

필요한 경우 CSS의 다음 속성들을 적절히 활용해주세요.

`@page`
`@media print`
`break-inside`
`page-break-inside`
`break-before`
`break-after`

# 10. 보고서 헤더·푸터

인쇄 화면에는 보고서 문서 느낌을 강화할 수 있도록 간결한 헤더와 푸터를 구성해주세요.

가능하다면 다음 요소를 사용합니다.

상단:

* 보고서 제목
* 분석 기간

하단:

* 작성일
* 페이지 번호 또는 문서 구분 정보

단, 브라우저별로 자동 페이지 번호 구현이 안정적이지 않은 경우 무리하게 구현하지 않아도 됩니다.

# 11. 보고서 작성 전 간단한 입력 기능

가능하면 `보고서 만들기`를 클릭했을 때 작은 설정 영역 또는 모달을 제공해주세요.

사용자가 다음 내용을 선택적으로 입력할 수 있게 합니다.

* 보고서 제목
* 작성 부서
* 작성자
* 보고 목적
* 특이사항 / 조치사항

입력하지 않은 항목은 보고서에서 자동으로 숨겨주세요.

이 정보는 브라우저 내부에서만 사용하고 별도의 데이터베이스 저장 기능은 필요하지 않습니다.

# 12. 보고서와 대시보드의 역할을 명확히 구분

대시보드는

**탐색하고 분석하는 화면**

이고,

보고서는

**결과를 전달하고 공유하는 문서**

입니다.

따라서 보고서 화면에서는 대시보드의 다음 요소들을 그대로 가져오지 마세요.

* 필터 버튼
* 드롭다운
* 보고서 선택 체크박스
* 대시보드 메뉴
* 인터랙션 버튼
* 불필요한 툴팁
* 웹앱용 컨트롤

보고서에는 **결론과 근거가 되는 정보만 남겨주세요.**

9. 인쇄 및 PDF 저장이 정상 작동하는지
